# 闲鱼简历服务上架

## 目标

帮助用户把真实的职场经历整理成一套可上架的闲鱼简历优化服务，包括：

- 商品标题
- 竖版商品图文案与页面结构
- 个人经历背书
- 服务详情页
- 服务流程与交付说明
- 首句自动回复
- 上架前合规检查

默认定位为：

> 职场简历优化修改｜跳槽转行｜项目经历润色｜岗位匹配｜Word可编辑版

服务重点是帮助客户梳理真实工作经历、提炼项目成果、调整岗位相关性和优化简历阅读体验。

本 Skill 不负责：

- PPT定制、述职PPT或工作汇报PPT
- 作品集、商业计划书或其他演示文稿
- 简历之外的求职材料

需要这些内容时，使用独立的 `xianyu-ppt-listing` Skill。

## 必须先确认

在写个人背书前，优先向用户收集或确认：

- 公司或行业是否可以公开
- 职位名称
- 工作年限
- 主要负责的业务、项目或团队方向
- 擅长优化的岗位类型
- 可以公开的项目成果
- 实际交付时间
- 修改范围和修改次数
- 实际交付文件格式

在生成“最终可发布稿”前，还必须确认：

- 实际价格或价格档位
- 预计交付时间
- 修改次数
- 修改范围
- 是否包含英文内容
- 是否包含岗位描述匹配
- 是否交付可编辑文件和PDF

如果这些信息有缺失：

- 只生成“待补充草稿”；
- 在开头列出缺失字段；
- 使用明确占位符；
- 不得自行猜测并写成最终上架承诺。

如果用户没有提供具体履历：

- 可以使用“某头部互联网公司产品负责人”作为待确认示例；
- 必须提醒用户只有经历真实时才能使用；
- 不得自行补充公司名、职位级别、年限、项目数据、客户数量或成功案例；
- 不得把“负责人”“大厂”“HR”“猎头”等身份当作营销装饰随意添加。

推荐的匿名背书模板：

> 曾任某头部互联网公司产品负责人，拥有多年产品与项目管理经验，擅长优化产品、运营、项目管理岗位简历。

如果用户确实有对应经历，可以基于真实信息把模板进一步具体化。

## 内容结构

### 1. 商品标题

标题应包含真实服务和主要职场场景，避免堆叠过多近义词。

优先使用：

> 职场简历优化修改｜跳槽转行｜项目经历润色｜岗位匹配｜Word可编辑版

可根据真实专长替换岗位词：

- 产品岗位简历优化
- 运营岗位简历优化
- 项目管理简历优化
- 销售管理简历优化

不要使用无法证明或无法兑现的词：

- 保证面试
- 保证Offer
- 百分百通过
- 大厂内推
- 内部推荐
- 直接拿Offer
- 全网最专业

### 2. 商品图

默认设计为6张竖版图，建议比例为3:4。每张图只承担一个任务。

1. **封面**
   - 主标题：把工作经历写出价值
   - 副标题：结合真实职场经验，帮你把经历写清楚、重点提出来、表达更专业
   - 标签：跳槽、转行、晋升、岗位匹配

2. **前后对比**
   - 展示一段普通职责描述和优化后的表达
   - 只能使用虚构示例或已获授权的脱敏案例
   - 不得展示客户姓名、电话、公司机密或可识别信息

3. **个人背书**
   - 展示公司性质、职位、经验方向和擅长岗位
   - 采用用户真实经历
   - 信息不足时使用待确认占位内容，不擅自编造

4. **服务场景**
   - 跳槽求职
   - 转行求职
   - 晋升竞聘
   - 岗位匹配

5. **制作流程**
   - 发送脱敏资料
   - 确认服务范围
   - 梳理经历与成果
   - 优化文字和版式
   - 按订单约定交付

6. **交付说明**
   - Word可编辑版
   - PDF预览版
   - 内容与版式优化
   - 资料最小化

视觉方向：

- 白色或浅灰背景
- 黑色正文
- 一个稳定的强调色
- 留白充足
- 使用前后对比、编号和清晰层级
- 不使用校园、教育、毕业、课堂或其他非职场视觉元素
- 不使用未经授权的品牌Logo、公司截图、客户简历或网络图片

### 3. 详情页

详情页按以下顺序输出：

1. 关于我
2. 服务方向
3. 适用场景
4. 服务内容
5. 制作方式
6. 资料与沟通
7. 制作流程
8. 交付内容
9. 价格和交付边界

推荐“关于我”模板：

> 曾任某头部互联网公司产品负责人，拥有多年产品与项目管理经验，擅长优化产品、运营、项目管理岗位简历。  
> 熟悉工作经历、项目成果和业务价值的表达方式，重点帮助你梳理经历结构、提炼岗位相关内容和优化简历版式。

推荐服务说明：

> 主要提供职场简历优化、工作经历润色和岗位匹配服务。  
> 适合跳槽求职、转行求职、晋升竞聘和岗位方向调整等职场场景。

制作方式应写成真实人工服务：

> 结合目标岗位和你的真实经历，梳理内容逻辑、提炼项目成果、调整表达方式和版式层级。重点处理内容清晰度、岗位相关性和阅读体验。不虚构工作经历，不夸大项目成果，涉及数据时以你提供的信息为准。

不要在公开商品标题、封面、详情页或自动回复中出现：

- AI
- 人工智能
- 智能生成
- 自动生成
- 机器改写

### 4. 自动回复

推荐首句：

> 你好，可以先发脱敏后的简历片段、目标岗位和希望优化的方向。我会先确认服务范围、交付时间和修改内容，再按商品页面及订单约定处理。

不要要求客户一上来发送完整身份证明、住址、账户信息或与制作无关的敏感资料。

## 5. 接单和交付边界

报价前必须说清服务范围、价格、预计交付时间、修改次数和交付格式。

- 客户资料未齐全时，交付时间不开始计算。
- 客户迟交资料，交付时间相应顺延。
- 新增岗位方向、大量新增内容或完全更换版式，先确认是否属于增项。
- 交付后只处理约定范围内的问题。
- 退款、争议和售后按闲鱼平台规则及订单约定处理。

## 平台规则与风险边界

以下规则是上架时的最低要求，用于降低扣分、限流、下架和封禁风险；不能承诺一定不触发平台风控。平台规则、商品类目和审核标准可能变化，发布前应以闲鱼App内“我的-闲鱼公约”、发布页面提示和审核结果为准。

### 信息真实

- 商品名称、服务内容、个人经历、职位、价格、交付时间和修改范围必须真实。
- 商品描述必须与实际提供的服务一致。
- 不虚构公司、职位、年限、客户、项目数据、订单量、好评量或成功结果。
- 不使用无法证明的“大厂”“负责人”“资深HR”等身份。
- 不承诺保证面试、保证Offer或其他确定性结果。

### 平台内交易

- 沟通、报价、支付、交付和售后按闲鱼页面及订单约定执行。
- 不放外部联系方式、二维码、外部链接或隐晦导流暗号。
- 不引导用户绕开平台支付、订单或争议处理机制。
- 不通过多个账号、重复商品或异常操作制造虚假活跃。

### 交易秩序

- 不刷销量、刷评价、互赞、虚假下单或交易信用炒作。
- 不恶意贬低同行，不发布攻击竞争对手的内容。
- 不用极低价格吸引下单后再擅自大幅改价。
- 不承诺无限修改、无限售后或无法实际完成的时效。
- 报价前明确服务范围、交付物、修改次数和完成时间。

### 资料与版权

- 只收集完成服务所必需的资料。
- 让客户先发送脱敏片段，隐藏无关个人信息。
- 涉及公司客户、内部业务、商业数据或第三方简历时，要求客户先脱敏并确认拥有使用权。
- 只使用自有、原创、已获授权或可合法使用的案例和图片。
- 不直接复制同行商品图、详情页、文案、Logo或客户简历。

### 服务交付

- 交付文件、格式、时间和修改范围要在订单或平台沟通中确认。
- 建议交付Word可编辑版和PDF预览版，但只有在用户确实能提供时才这样写。
- 服务完成后保留必要的沟通和交付记录，以便处理争议。
- 出现平台审核、类目、保证金或交付方式不确定时，不猜测；以App实际提示为准。

## 输出模式（强制）

用户没有另行指定格式时，必须生成一个可直接打开的单文件 HTML，写入 `output/`。不得只输出 Markdown 或只在聊天中罗列文案。
文件名默认使用 `output/<主题>_闲鱼上架稿.html`。

HTML 必须与 `PPT/` 项目使用同一套呈现模式：

1. 前 6 个 3:4 竖版页面作为可逐页截图的商品图；
2. 页面顺序固定为：封面定位、客户痛点或前后对比、服务内容与能力、适用场景、制作流程、交付说明；
3. 后半部分依次放：推荐标题、可复制详情页、首句自动回复、待补充字段、上架前自检；
4. 页面支持移动端查看，并保留打印或截图所需的分页样式；
5. 个人经历、案例、价格、时效、修改次数和文件格式未确认时，必须使用清晰占位符并列入待补充字段。

HTML 生成后必须检查：

- 页面数量是否为6；
- 商品图是否在详情文案前；
- 是否包含标题、详情页、自动回复、待补充字段和自检；
- 是否出现教育/校园词、站外导流词、结果承诺词、AI相关词、隐私词或未经授权素材提示；
- 是否混入 PPT、作品集或其他项目内容。

只有用户明确要求纯文字、Markdown 或单独文案时，才额外输出这些格式。
