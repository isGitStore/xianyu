# 闲鱼PPT服务上架

## 目标

把真实的PPT制作能力整理成一套可上架的闲鱼服务，包括商品标题、6张商品图、个人经历背书、详情页、制作流程、交付说明、自动回复和上架检查。

默认定位：

> 工作汇报PPT定制｜述职竞聘｜项目复盘｜年度总结｜商业展示

本 Skill 不负责简历制作、简历优化、作品集、校园教育类PPT或未经授权的企业商业材料。

需要简历服务时，使用独立的 `xianyu-resume-listing` Skill。

## 必须先确认

先确认：

- 公司或行业是否可以公开
- 职位名称和工作年限
- 负责过的业务、项目或汇报场景
- 擅长的PPT类型
- 可公开的案例类型
- 预计页数、交付时间、修改轮次和文件格式

没有具体履历时，只能使用待确认示例：

> 曾任某头部互联网公司产品负责人，拥有多年产品与项目管理经验，熟悉工作汇报、项目复盘和业务展示的内容结构与表达方式。

不得自行补充公司名、职位级别、年限、客户名称、项目数据或商业成果。

## 商品结构

### 标题

推荐：

> 工作汇报PPT定制｜述职竞聘｜项目复盘｜年度总结｜商业展示

可按真实能力替换场景：

- 产品汇报PPT
- 项目复盘PPT
- 述职竞聘PPT
- 年度总结PPT
- 客户提案PPT
- 商业计划书PPT

不要使用：

- 保证晋升
- 保证竞聘成功
- 保证融资
- 领导看了必过
- 大厂内部模板

### 6张商品图

1. 封面：工作汇报PPT定制，把成果、逻辑和重点讲清楚。
2. 前后对比：展示信息堆叠页面与层级清楚页面。
3. 关于我：展示真实公司性质、职位、经验方向和擅长场景。
4. 服务范围：工作汇报、述职竞聘、项目复盘、年度总结、客户提案、商业展示。
5. 制作流程：发送资料、确认页数、梳理逻辑、调整页面、按订单交付。
6. 交付说明：PPTX可编辑版、PDF预览版、页面结构和视觉统一。

案例必须使用虚构示例、原创案例或已授权且脱敏的案例。不得出现客户姓名、公司机密、内部数据、未授权Logo或第三方素材。

视觉方向：

- 3:4竖版
- 白色、浅灰或深色职场风
- 标题优先表达页面结论
- 图表和数据以客户资料为准
- 保证投屏可读，控制页面信息密度
- 不使用校园、教育、课程作业或非职场场景元素

## 详情页结构

按以下顺序输出：

1. 关于我
2. 服务方向
3. 适用场景
4. 服务内容
5. 制作流程
6. 资料与沟通
7. 交付内容
8. 价格、页数和修改边界

推荐背书：

> 曾任某头部互联网公司产品负责人，拥有多年产品与项目管理经验，熟悉工作汇报、项目复盘和业务展示的内容结构与表达方式。擅长把复杂信息整理成清晰的汇报逻辑，并根据使用场景调整页面标题、内容层级和视觉表达。

推荐服务说明：

> 主要提供工作汇报、述职竞聘、项目复盘、年度总结、客户提案和商业展示PPT定制服务。重点处理内容结构、页面标题、信息层级、图表表达和整体视觉统一。

推荐边界说明：

> 页面内容以客户提供的资料为基础整理，不虚构项目数据、业务成果和公司信息。具体页数、交付时间、修改次数和文件格式以商品页面及订单约定为准。

公开文案中不出现AI、人工智能、智能生成、自动生成、机器制作等字样。

## 自动回复

> 你好，可以先发PPT用途、汇报对象、预计页数、原始资料和期望完成时间。我会先确认页面范围、交付格式和修改内容，再按商品页面及订单约定处理。

不要要求客户发送与制作无关的账户信息、个人证件或企业机密。

## 规则

- 商品、个人经历、价格、页数、交付时间和修改范围必须真实。
- 只能承诺制作范围和文件交付，不能承诺晋升、竞聘、融资或汇报结果。
- 沟通、报价、支付、交付和售后按闲鱼页面及订单约定执行。
- 不放外部联系方式、二维码、外部链接或隐晦导流暗号。
- 不刷销量、刷评价、互赞、虚假下单或交易信用炒作。
- 不复制同行商品图、详情页、文案或第三方商业模板。
- 客户内部资料、客户数据、经营数据和商业计划必须先确认授权并脱敏。
- 超出原订单范围的新增页面或大幅改稿，先在平台内确认价格和时间。
- 规则可能变化，发布前以闲鱼App内“闲鱼公约”、发布页面提示和审核结果为准。

## 输出模式（强制）

用户没有另行指定格式时，必须生成一个可直接打开的单文件 HTML，写入 `output/`。不得只输出 Markdown 或只在聊天中罗列文案。
文件名默认使用 `output/<主题>_闲鱼上架稿.html`。

HTML 必须与 `简历/` 项目使用同一套呈现模式：

1. 前 6 个 3:4 竖版页面作为可逐页截图的商品图；
2. 页面顺序固定为：封面定位、客户痛点或页面前后对比、服务内容与能力、适用场景、制作流程、交付说明；
3. 后半部分依次放：推荐标题、可复制详情页、首句自动回复、待补充字段、上架前自检；
4. 页面支持移动端查看，并保留打印或截图所需的分页样式；
5. 个人经历、案例、价格、页数、时效、修改次数和交付格式未确认时，必须使用清晰占位符并列入待补充字段。

HTML 生成后必须检查：

- 页面数量是否为6；
- 商品图是否在详情文案前；
- 是否包含标题、详情页、自动回复、待补充字段和自检；
- 是否出现校园/教育词、站外导流词、结果承诺词、AI相关词或未经授权素材提示；
- 是否混入简历服务内容。

只有用户明确要求纯文字、Markdown 或单独文案时，才额外输出这些格式。

## 项目沉淀要求

每完成一版 PPT 项目成品后，必须同步更新项目规则和 Skill：

1. 更新 `PPT/AGENTS.md`，记录新确认的服务范围、输出结构、交付边界和禁用表达。
2. 更新本 `SKILL.md`，记录可复用的执行流程、页面结构、文案模板和检查步骤。
3. 必要时更新 `references/rules.md`，补充平台风险、项目串用风险和上架核查项。
4. 最终回复中说明 HTML 成品、规则和 Skill 分别更新了什么。
